# Yarnelo для Linux: установка и использование

[English](LINUX.md) · **Русский**

Linux-версия Yarnelo — **preview** на Qt 6: до 30 ярлыков, 1–4 ряда, регулируемая прозрачность фона, размер значков, плавное увеличение и перестановка. Python и Qt включены в готовые сборки.

Пакеты скачиваются только из [релизов feogrim-cloud/Yarnelo](https://github.com/feogrim-cloud/Yarnelo/releases). Скачайте также `SHA256SUMS` и выполните `sha256sum --check SHA256SUMS --ignore-missing` в той же папке.

## Совместимость и окружение

Предусмотрены отдельные нативные сборки для **x86_64** и **ARM64**. Выбирайте пакет по архитектуре процессора и версии системных библиотек:

| Архитектура из `uname -m` | Минимальный glibc | Примеры подходящих систем | Имена пакетов |
| --- | --- | --- | --- |
| `x86_64` (Intel/AMD, также `amd64`) | **2.35** | Ubuntu 22.04+, Debian 12+, Mint 21+ | `amd64.deb`, `x86_64.AppImage`, `x86_64.rpm`, `x86_64.tar.gz` |
| `aarch64` (ARM 64 бита, также `arm64`) | **2.39** | Ubuntu 24.04+, Debian 13+, достаточно новые Fedora / другие дистрибутивы | `arm64.deb`, `aarch64.AppImage`, `aarch64.rpm`, `aarch64.tar.gz` |

Это нижние границы используемых библиотек, а не гарантия проверки каждого выпуска дистрибутива. Архитектуру и glibc можно проверить командами:

```bash
uname -m
getconf GNU_LIBC_VERSION
```

Сопоставьте оба значения с таблицей. ARM64-библиотеки Qt требуют более новый glibc, чем x86_64: **Debian 12 и Ubuntu 22.04 не поддерживаются готовыми ARM64-файлами**. ARM-компьютеру, например Raspberry Pi, нужна подходящая 64-битная графическая ОС и библиотеки. 32-битный образ, прежние версии Raspberry Pi OS и образ без рабочего стола не получают совместимость автоматически. Для всех сборок нужен графический рабочий стол. Сборки для 32-битного Linux, Alpine/musl и Ubuntu 20.04 в этот выпуск не входят.

**Рекомендуется сеанс X11 с композитором.** Панель просит оконный менеджер держать её ниже обычных окон и не резервирует часть экрана. В Wayland-сеансе для готовых пакетов нужен XWayland. При ошибке выбора платформы можно явно указать X11:

```bash
QT_QPA_PLATFORM=xcb yarnelo
# Для переносной сборки:
QT_QPA_PLATFORM=xcb ./Yarnelo-Linux-x86_64.AppImage
```

Нативный Wayland доступен только при самостоятельном запуске из исходников с соответствующими Qt-плагинами и остаётся экспериментальным. Позиционирование, порядок окон и значок в области уведомлений зависят от окружения. Linux-preview пока не повторяет Windows-механизм определения перекрытия и полноэкранных игр. Если конкретный композитор выводит панель поверх игры, выйдите из Yarnelo через её меню.

Для открытия файлов нужен `xdg-open`, для ярлыков `.desktop` — `gio`, для Корзины — файловый менеджер с поддержкой `trash:///`, обычно через GVfs. Пакеты DEB/RPM запрашивают основные зависимости автоматически; поведение Корзины зависит от файлового менеджера.

## Ubuntu, Debian и Linux Mint: DEB

В папке со скачанным пакетом:

```bash
sudo apt install ./Yarnelo-Linux-amd64.deb
yarnelo
```

Для **ARM64 с Ubuntu 24.04+ / Debian 13+** установите ARM64-пакет:

```bash
sudo apt install ./Yarnelo-Linux-arm64.deb
yarnelo
```

Используйте `apt install ./файл.deb`, чтобы менеджер пакетов установил зависимости. Yarnelo появится в меню приложений. Файлы программы находятся в `/opt/yarnelo`, команда — `/usr/bin/yarnelo`.

## Fedora: RPM

```bash
sudo dnf install ./Yarnelo-Linux-x86_64.rpm
yarnelo
```

RPM содержит требования к системным библиотекам по их SONAME, а не только по Fedora-названиям пакетов. Он устанавливает программу в `/opt/yarnelo`, команду `yarnelo` и пункт меню приложений.

Для **Fedora ARM64 с glibc 2.39+** используйте:

```bash
sudo dnf install ./Yarnelo-Linux-aarch64.rpm
yarnelo
```

## openSUSE: RPM

В достаточно новом выпуске с glibc 2.35+:

```bash
sudo zypper install ./Yarnelo-Linux-x86_64.rpm
yarnelo
```

Для ARM64 с glibc 2.39+ подставьте `Yarnelo-Linux-aarch64.rpm`. Отдельная проверка установки в openSUSE пока не выполнена; если менеджер пакетов не может разрешить зависимости, не обходите их проверку. Можно воспользоваться AppImage или TAR.GZ нужной архитектуры с установленными системными библиотеками.

## AppImage: один исполняемый файл

```bash
chmod +x ./Yarnelo-Linux-x86_64.AppImage
./Yarnelo-Linux-x86_64.AppImage
```

Для **ARM64** с glibc 2.39+:

```bash
chmod +x ./Yarnelo-Linux-aarch64.AppImage
./Yarnelo-Linux-aarch64.AppImage
```

Права администратора не нужны. Поместите файл в постоянную папку, например `~/Applications`, если хотите создать на него ярлык. Сам по себе AppImage не добавляет пункт в меню приложений и не включает автозапуск.

Если система сообщает об отсутствии FUSE, используйте встроенное извлечение и запуск:

```bash
APPIMAGE_EXTRACT_AND_RUN=1 ./Yarnelo-Linux-x86_64.AppImage
```

Для ARM64 в этой же команде подставьте `Yarnelo-Linux-aarch64.AppImage`. Этот способ временно извлекает приложение и удаляет временные файлы после выхода. Альтернативный вариант без FUSE — TAR.GZ ниже. Формат AppImage не отменяет требования к архитектуре и минимальному glibc.

Если Qt сообщает, что не может загрузить плагин `xcb`, в Ubuntu / Debian / Mint установите недостающие системные компоненты:

```bash
sudo apt install libxcb-cursor0 libxkbcommon-x11-0 libxcb-icccm4 \
  libxcb-image0 libxcb-keysyms1 libxcb-render-util0 libxcb-xinerama0 \
  libgl1 libegl1 xdg-utils libglib2.0-bin gvfs-backends
```

Для диагностики запуска используйте `QT_DEBUG_PLUGINS=1 ./Yarnelo-Linux-x86_64.AppImage`: вывод укажет конкретную недостающую библиотеку. В других дистрибутивах установите соответствующий пакет своим менеджером пакетов.

## TAR.GZ: переносная папка, в том числе для Arch Linux

```bash
mkdir -p "$HOME/Applications"
tar -xzf ./Yarnelo-Linux-x86_64.tar.gz -C "$HOME/Applications"
"$HOME/Applications/Yarnelo/yarnelo"
```

Для **ARM64** подставьте `Yarnelo-Linux-aarch64.tar.gz`. Путь к распакованному исполняемому файлу будет тем же. Скачивайте только подходящую архитектуру.

Распакуйте архив полностью. Исполняемый файл `yarnelo` работает вместе с соседней папкой `_internal`; перемещать отдельно только один файл нельзя. Python из системы для этой сборки не требуется. Системные X11/OpenGL/GLib-библиотеки и средства `xdg-open`/`gio` остаются зависимостями окружения.

В Arch при отсутствии компонентов установите их пакетным менеджером; обновление системы выполняйте по обычным правилам Arch, без частичного обновления библиотек.

### Пункт меню для переносной версии

У DEB/RPM он создаётся автоматически. Для TAR.GZ из предыдущего примера можно создать его вручную:

```bash
mkdir -p "$HOME/.local/share/applications"
cat > "$HOME/.local/share/applications/yarnelo.desktop" <<EOF
[Desktop Entry]
Type=Application
Name=Yarnelo
Exec="$HOME/Applications/Yarnelo/yarnelo"
Icon=$HOME/Applications/Yarnelo/_internal/assets/Yarnelo-Icon-256.png
Terminal=false
Categories=Utility;
StartupNotify=false
EOF
```

Если программа расположена в другом месте, исправьте `Exec` и `Icon`. Для AppImage в `Exec` укажите полный путь к `.AppImage`, а для `Icon` сохраните [значок Yarnelo](https://github.com/feogrim-cloud/Yarnelo/blob/main/assets/Yarnelo-Icon-256.png) в постоянной папке и укажите его полный путь. Если используется обход FUSE, команда в ярлыке должна начинаться с `env APPIMAGE_EXTRACT_AND_RUN=1`, затем идёт путь к AppImage.

## Автозапуск при входе

Правая кнопка по панели → **Настройки… → Запускать при входе в систему**, затем **OK**. По умолчанию галочка выключена. Чтобы отключить автозапуск, снимите её и нажмите **OK**; **«Отмена»** оставляет регистрацию без изменений. Галочка отражает текущую регистрацию, включая отключённую запись, и не включает автозапуск заново по старой настройке профиля.

Yarnelo создаёт `yarnelo.desktop` в `$XDG_CONFIG_HOME/autostart` или по умолчанию в `~/.config/autostart` только для вашей учётной записи. Права администратора не нужны. Запись запускает именно эту копию: исполняемый файл DEB/RPM, полную папку TAR.GZ, интерпретатор и скрипт исходной версии либо оригинальный AppImage. Для AppImage сохраняется постоянный внешний файл, а не временная папка монтирования или извлечения; при использовании запуска без FUSE этот режим сохраняется.

**Перед включением автозапуска разместите AppImage, TAR.GZ или исходную версию в постоянной папке.** Перед переносом программы или её окружения Python выключите автозапуск и нажмите **OK** из прежнего места. Переместите программу, затем включите автозапуск и нажмите **OK** из нового места. Временная папка загрузки или распаковки перестанет работать после удаления файлов. Если программа уже перенесена, проверьте `Exec=` в пользовательском `autostart/yarnelo.desktop`; убедившись, что там указана ваша прежняя копия Yarnelo, удалите устаревший файл и включите автозапуск из новой копии.

Отключение убирает собственную пользовательскую запись Yarnelo. Если иначе сработала бы её системная запись, программа создаёт пользовательское переопределение `Hidden=true`. Yarnelo не меняет `/etc` и записи других приложений. Если раньше вы вручную добавляли отдельную команду в автозапуск окружения, удалите дубликат; для старых выпусков Yarnelo ручной способ остаётся доступен.

Окружение должно поддерживать автозапуск XDG, как обычно делают GNOME, KDE Plasma и Xfce. Запуск произойдёт при следующем входе в графический сеанс; момент и возможную задержку определяет окружение рабочего стола. Фиксированная задержка задачи Windows в 10 секунд на Linux не распространяется. Автоматические проверки охватывают создание и удаление записи и работу настроек; они не подтверждают вход в систему во всех окружениях.

## Ярлыки и настройки

Перетащите `.desktop`, файл или папку на панель. Кнопка **+** и контекстное меню также добавляют ярлыки, «Компьютер» и Корзину. «Компьютер» открывает корень файловой системы. Порядок меняется перетаскиванием. В двух столбцах окна **«Настройки…»** без вертикальной прокрутки доступны непрозрачность фона, скругление (0 — прямые углы, 100 — капсула), размер значков, увеличение и подписи.

Включите **«Показывать подписи»** для компактных однострочных подписей под значками. Длинные подписи сокращаются по ширине; название также видно при наведении на значок. Выбор показа подписей не сбрасывается при обновлении.

Галочка **«Автоматически добавлять новые ярлыки с рабочего стола»** по умолчанию выключена. Включите её в настройках и нажмите **OK**, чтобы учитывать новые `.desktop`, появляющиеся на рабочем столе во время работы Yarnelo. При включении опции или запуске приложения прежние значки остаются без изменений; обычные файлы и папки игнорируются. Программа дожидается окончания записи ярлыка, пропускает дубликаты и не меняет оригиналы. При лимите 30 значков новый ярлык остаётся на рабочем столе и не ставится в очередь; освободите место и добавьте его вручную. Выключение галочки оставляет ручное добавление перетаскиванием или через **+**.

Выберите расположение по центру сверху, снизу, слева или справа; боковая панель вертикальная, значки обычной ориентации. Ручка включает свободное размещение. Выбранные 1–4 ряда у бокового края становятся столбцами. При нехватке места автоматически добавляются ряды/столбцы, затем при необходимости уменьшаются значки; сохранённый выбор не меняется. Размещение по-прежнему зависит от описанных выше ограничений композитора X11/XWayland.

Через **Язык / Language → Русский / English** в контекстном меню можно сменить язык без перезапуска. Выбор сохраняется в профиле. При первом запуске используется русский для русской локали системы, английский — для остальных. Имена ваших файлов и ярлыков не переименовываются.

### Темы

В **Настройки → Тема** выберите **Dusk («Сумерки», базовая)**, **Frost («Матовое стекло»)**, **Graphite («Матовый графит»)**, **Ember («Тёмная бронза»)** или **Aurora («Ночной индиго»)** и нажмите **OK**. **«Отмена»** оставляет сохранённую тему и настройки без изменений. Меню и настройки используют выбранную палитру; в светлой Frost текст остаётся контрастным и тёмным.

Dusk использует общий стиль элементов управления остальных четырёх тем: акцентные ползунки, оформленные в цветах темы кнопки и меню. Прежние цвета панели Dusk и анимации сохраняются.

У каждой темы запоминаются собственные непрозрачность и скругление. При первом выборе используются **76% / 22** для Frost, **96% / 12** для Graphite, **85% / 16** для Ember и **88% / 24** для Aurora. После обновления прежний вид остаётся в Dusk с уже выбранными вами параметрами фона. Возврат к Dusk или другой настроенной теме восстанавливает её сохранённый фон. Смена темы не сбрасывает размер значков, увеличение, ряды, положение, компактные подписи, автозапуск и автоматическое добавление ярлыков.

Темы также задают характер анимаций наведения, нажатия и перетаскивания. Край Aurora подсвечивается при взаимодействии; в покое панель не переливается. Оформление использует нативные цвета Qt, полупрозрачность, границы и тени. Описанные выше ограничения композитора X11/XWayland остаются в силе.

### Хранение ярлыков

Linux-версия сохраняет ссылки на исходные файлы и **не перемещает их с рабочего стола**. Если хотите убрать исходники, сначала перенесите их в постоянную папку, затем добавьте оттуда. Удаление значка из панели удаляет только ссылку внутри Yarnelo.

Профиль находится в `$XDG_CONFIG_HOME/yarnelo/settings.json` или по умолчанию в `~/.config/yarnelo/settings.json`. У Windows и Linux разные профили: автоматического импорта Windows-ярлыков `.lnk` / `.url` нет.

## Обновление и удаление

Перед заменой файлов закройте Yarnelo через контекстное меню панели или значок в области уведомлений. Для резервной копии сохраните каталог `yarnelo` из своей папки конфигурации.

- **DEB:** установите новый `.deb` той же командой `sudo apt install ./...`; удаление — `sudo apt remove yarnelo`.
- **RPM / Fedora:** обновление — `sudo dnf upgrade ./Yarnelo-Linux-x86_64.rpm`; удаление — `sudo dnf remove yarnelo`.
- **RPM / openSUSE:** установите новый RPM через `sudo zypper install ./...`; удаление — `sudo zypper remove yarnelo`.
- **AppImage:** замените файл новым выпуском и снова разрешите исполнение через `chmod +x`; удаление — удалите сам файл.
- **TAR.GZ:** распакуйте новый выпуск в прежнее постоянное место; удаление — удалите папку программы.

Перед удалением Yarnelo снимите галочку **Настройки → Запускать при входе в систему** и нажмите **OK**, чтобы убрать регистрацию автозапуска текущего пользователя. Удаление пакета не очищает настройки в домашних папках пользователей. Обновление и удаление сохраняют профиль; добавленные вручную пункты меню и дублирующие команды автозапуска удаляются отдельно. Собственные файлы, папки и `.desktop`, на которые указывает панель, не затрагиваются.

## Для разработчиков и лицензии

Запуск из исходников и проверка интерфейса описаны в [linux/README.md](../linux/README.md). Скрипт `scripts/Package-Linux.sh` выполняет нативную сборку на Ubuntu 22.04 x86_64 или Ubuntu 24.04 ARM64 и создаёт тот же автономный GUI для TAR.GZ, AppImage, DEB и RPM. Архитектура определяется по среде сборки; переименование x86_64-файла не превращает его в ARM64. Автоматические проверки не подтверждают поведение на каждом физическом ARM-устройстве, окружении рабочего стола или в каждой игре.

Qt-библиотеки подключаются динамически и могут быть заменены совместимыми изменёнными версиями с соблюдением их лицензий. См. [LICENSE](../LICENSE).
